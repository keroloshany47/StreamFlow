# Java Transaction Producer

High-throughput Kafka producer written in Java. Generates synthetic financial transactions and publishes them to the `financial_transactions` topic at maximum speed using a multi-threaded executor pool.

---

## Source Structure

```
src/main/java/com/datamasterylab/
├── TransactionProducer.java   ← entry point, threading, Kafka config
└── dto/
    └── Transaction.java       ← data model + random data generator
```

---

## How It Works

```
main()
  │
  ├── createTopicIfNotExists()     AdminClient checks / creates topic
  │
  ├── KafkaProducer<String,String> shared across all threads (thread-safe)
  │
  ├── Thread 0  → throughput reporter (logs records/sec every 1s)
  ├── Thread 1  → produce loop
  ├── Thread 2  → produce loop
  └── Thread N  → produce loop   (N = CPU cores - 1)
```

Each producer thread runs an infinite loop:
1. `Transaction.randomTransaction()` — generates a new random transaction
2. `ObjectMapper.writeValueAsString()` — serializes to JSON
3. `producer.send()` — async send with a callback that increments the counter on success

## Transaction Schema

Generated by `Transaction.randomTransaction()`:

| Field | Type | Example | Range |
|---|---|---|---|
| `transactionId` | String (UUID) | `a1b2c3...` | random UUID |
| `userId` | String | `user42` | user0 – user99 |
| `merchantId` | String | `merchant7` | merchant0 – merchant49 |
| `amount` | double | `234.57` | 10.0 – 510.0 |
| `transactionTime` | long (epoch ms) | `1715500000000` | current time |
| `transactionType` | String | `purchase` | purchase / refund |
| `location` | String | `NY, USA` | NY, USA / LA, USA |
| `paymentMethod` | String | `credit_card` | credit_card / debit_card |
| `isInternational` | boolean | `true` | true / false |
| `currency` | String | `USD` | USD / EUR |

>  Anomaly detection in Spark triggers at `amount > 140,000`. The current generator caps at ~510 — adjust `randomTransaction()` to inject anomalies for testing.

## Kafka Producer Configuration

| Config | Value | Why |
|---|---|---|
| `BATCH_SIZE` | 512 KB | large batches = fewer network round trips |
| `LINGER_MS` | 10ms | wait to fill batch before sending |
| `COMPRESSION_TYPE` | snappy | fast compression, ~2–3x size reduction |
| `ACKS` | 1 | leader ack only — max throughput, small durability trade-off |
| `BUFFER_MEMORY` | 256 MB | in-memory buffer before backpressure kicks in |
| `MAX_IN_FLIGHT` | 5 | 5 unconfirmed requests per connection |
| `SEND_BUFFER` | 1 MB | OS-level TCP send buffer |

### Topic Config
| Config | Value |
|---|---|
| Topic name | `financial_transactions` |
| Partitions | 16 |
| Replication factor | 3 |
| Bootstrap servers | `localhost:29092,39092,49092` |

## How to Run

### Prerequisites
- JDK 11+
- Gradle (wrapper included)
- Kafka brokers running (via `docker compose up -d`)

### Build
```bash
./gradlew build
```

### Run
```bash
./gradlew run
```

Or run the built JAR directly:
```bash
java -jar build/libs/KafkaSparkArch-1.0-SNAPSHOT.jar
```

### Expected output
```
INFO  Starting 8 producer threads on 8 cores
INFO  Topic 'financial_transactions' already exists.
INFO  Throughput: 280,000 records/sec | Total: 280,000
INFO  Throughput: 310,000 records/sec | Total: 590,000
```

### Graceful shutdown
`Ctrl+C` triggers the shutdown hook — flushes remaining buffered messages before exit:
```
INFO  Shutting down — flushing remaining messages...
INFO  Done. Total sent: 4,200,000
```

---

## Scaling

The producer automatically uses all available CPU cores:
```java
private static final int NUM_THREADS = Runtime.getRuntime().availableProcessors();
```

One thread is reserved for the throughput reporter, the rest are producers. On a machine with 8 cores you get 7 producer threads running in parallel.

To cap CPU usage on a shared machine:
```java
private static final int NUM_THREADS = 4;  // hard-code instead
```
